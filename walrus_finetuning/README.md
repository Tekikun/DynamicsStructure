# Walrus zero-shot / fine-tuning for MEGNO time evolution

Zero-shot testing and fine-tuning Polymathic AI's **Walrus** foundation model
(github.com/PolymathicAI/walrus) to predict MEGNO(a,e) chaos-map evolution
over time, using the datasets from the companion `megno_data_generation/`
release.

## Directory structure

```
code/
  configs/extended_config.yaml   Walrus model+trainer hydra config
  checkpoints/                   put the pretrained walrus.pt here (not
                                  included -- see Setup)
  run_walrus_megno.py            shared utilities: build model from
                                  checkpoint, build a trajectory example,
                                  autoregressive rollout
  run_walrus_time_evolution.py   ZERO-SHOT evaluation (also doubles as the
                                  preprocessing step: loads/clips/nan-fills
                                  a MEGNO_stack npz into the model's input
                                  format)
  eval_finetuned_time_evolution.py  evaluate a fine-tuned checkpoint the
                                  same way, for direct zero-shot comparison
  finetune_walrus_time_evolution.py       NARROW fine-tune (frozen backbone;
                                  only the new field's embed/decoder-head)
  finetune_walrus_time_evolution_full.py  FULL fine-tune (entire model
                                  unfrozen, matches Walrus's own recipe)
  launch_zeroshot.sh
  launch_narrow_finetune.sh
  launch_full_finetune.sh
  launch_full_finetune_resume.sh

Data/
  MEGNO_maps/                    input: .npz datasets from megno_data_generation/
  Walrus_results/                output: checkpoints, eval outputs, plots
```

## Environment and dependencies

Requires **Python 3.11** (a Walrus dependency, `the_well`, needs it).

```bash
python3.11 -m venv .venv
source .venv/bin/activate

pip install torch hydra-core omegaconf
git clone https://github.com/PolymathicAI/walrus code/walrus
pip install -e code/walrus   # installs `walrus` + `the_well`
```

Download the pretrained checkpoint (HuggingFace `polymathic-ai/walrus`) to
`code/checkpoints/walrus.pt`.

Populate `Data/MEGNO_maps/` with `.npz` datasets generated by the companion
`megno_data_generation/` release (e.g. `megno_time_evolution_all_ma_1024x512.npz`).

**Hardware notes:**
- Runs **CPU-only** in this package. Apple Silicon (MPS) lacks
  `ConvTranspose3d`, which Walrus's decoder needs, and it's a hard error
  rather than a fallback path -- `PYTORCH_ENABLE_MPS_FALLBACK` does not help.
- Set `OMP_NUM_THREADS` to your physical core count before any script here;
  PyTorch otherwise defaults to near-single-threaded.
- `gradient_checkpointing_freq=2` (already set in the full fine-tune script)
  is important for speed, not just memory: on CPU it gave a ~5.6x speedup
  over leaving it unset, because the bottleneck is memory *bandwidth*
  moving activations around, not capacity.
- macOS has no `timeout` command; if you need to wall-clock-bound an
  invocation (recommended for large-MA-count eval sweeps), wrap it with
  Python's `subprocess.run(..., timeout=...)` instead.

## Commands

Run from inside `code/` (scripts use `../Data/...`-relative I/O paths,
matching the layout above).

### 1. Zero-shot evaluation

```bash
./launch_zeroshot.sh
```
`MEGNO_EVAL_MA` (comma-separated MA values) restricts evaluation to a subset
-- important on high-MA-count datasets, where a full autoregressive rollout
over every MA is prohibitively slow (each rollout step re-runs the model
over a growing input window; cost scales with both MA count and rollout
depth).

### 2. Fine-tune

```bash
./launch_narrow_finetune.sh   # frozen backbone: embed/decoder-head only
./launch_full_finetune.sh     # full model unfrozen (Walrus's own recipe)
./launch_full_finetune_resume.sh   # continue an existing run for more epochs
```
Both fine-tune scripts are env-var configurable (grep `os.environ.get` in
each for the full list): `FT_HELDOUT_MA`, `FT_EPOCHS`, `FT_WINDOW_STRIDE`
(subsample training windows), `FT_TRAIN_MA_STRIDE` (full fine-tune only --
subsample which MA values are trained on, e.g. every-3rd, to keep epoch
time tractable at high MA counts), `FT_RESUME_CKPT`/`FT_LR`/`FT_GRAD_CKPT_FREQ`.

### 3. Evaluate a fine-tuned checkpoint

```bash
MEGNO_DATA_SUFFIX=_1024x512 MEGNO_N_STEPS_INPUT=5 \
  python eval_finetuned_time_evolution.py walrus_time_evolution_finetuned_1024x512_in5.pt
```

## Expected outputs

Each run prints per-MA correlation (predicted vs. true MEGNO(a,e) map,
Pearson r) at every forecast year, plus overall/held-out/train means, and
saves: a loss curve, a held-out-vs-zero-shot accuracy plot, an `.npz` with
the raw per-MA correlation arrays, and a true-vs-predicted map comparison
figure for MA=60.

Reference numbers from the original 16-MA, 1024x512, 5-frame-input setup
(held-out MA = 60, 240, 330; predicting years 60-100 from years 10-50):

| Run | MA60 | MA240 | MA330 | held-out mean |
|---|---|---|---|---|
| zero-shot | 0.775 | 0.590 | 0.723 | 0.696 |
| narrow (frozen backbone) fine-tune | 0.775 | 0.590 | 0.723 | 0.696 |
| full (unfrozen) fine-tune, converged (~epoch 4) | 0.785 | 0.599 | 0.735 | 0.711 |

The narrow fine-tune matching zero-shot to 3 decimal places, on every held-out
MA, is the key negative result: the "copy the last input frame forward"
behavior lives in the frozen processor blocks, which an embedding/decoder-head-
only fine-tune never touches. The full fine-tune's modest (+0.015) but real
gain converges within about 4-5 epochs; further epochs on the same training
MA values do not improve it further (tested out to 10 epochs).

On a later, fairer-comparison task (fine-grained 180-MA dataset,
`N_STEPS_INPUT=25`, predicting years 52-100 from years 2-50, so the model has
a full 50-year input context rather than 10 -- much closer to the original
task's information content), the full fine-tune's gain over zero-shot was
similarly modest and stable (0.746 -> 0.757, converging by epoch 3-5, no
overfitting through epoch 9). The narrow fine-tune was not re-tested on this
fairer task; given the mechanism identified above (the effect lives in the
frozen processor blocks), it is expected to show the same null result.
